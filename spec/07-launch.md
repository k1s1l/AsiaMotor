# Запуск магазина: каталог, заявки, хостинг

## 1. Каталог из прайса 1С

Каталог сайта строится из прайса магазина — того же Excel, что выгружается из 1С (`Asia_Motor_price_current_stock.xls`).

```bash
npm run catalog:import -- путь/к/Asia_Motor_price_current_stock.xls
```

**Что берётся из прайса:**

| Поле прайса | На сайте |
|---|---|
| группы «Марка → Модель» | совместимость товара и подбор «Моё авто»; товар, указанный под несколькими моделями, — один товар с несколькими моделями |
| «Номенклатура» | название (окончание «, шт» убирается) |
| «Артикул» | артикул, поиск |
| «Номенклатура.Код» | код товара (ID на сайте, не меняется между выгрузками) |
| «Наличие» | «В наличии» / «Осталось N шт.»; в корзину нельзя положить больше остатка |
| «Розница грн» | цена |
| дата в шапке | «Цены и наличие — по состоянию на …» |

**Что НЕ публикуется:** оптовые цены, цена предоплаты, курс, номер карты и ФИО из шапки прайса. Сам файл прайса в репозиторий не попадает — он внесён в `.gitignore`.

**Категории.** В прайсе их нет, поэтому товары раскладываются по 11 разделам магазина по названию. Правила лежат в `scripts/catalog-rules.ts`. Импорт печатает строки, которые не попали ни в один раздел. Такие строки не публикуются, пока для них не добавлено правило.

**Текущая выгрузка (прайс от 30.10.2026):**
- 10 745 строк, 2 639 уникальных товаров — все опубликованы;
- 33 марки, 164 модели;
- одна строка «Тестовая — не для продажи» исключена;
- у 3 товаров нет марки и модели (группа «СТО / разнопрофильные»): они показаны без совместимости.

**Чего в прайсе нет и на сайте не показывается:**
- фото;
- описания;
- производитель;
- годы выпуска и двигатели.

Ничего из этого не придумывается.

### Фото товаров

Есть два способа добавить фото — оба подхватываются следующим запуском импорта:

1. **Файлами.** Положите фото в `public/products/` и назовите их артикулом или кодом 1С: `1301100XKZ36A.jpg`, `1301100XKZ36A-2.jpg`, `ЦБ-00000147.webp`. Подходят `jpg`, `png`, `webp`, `avif`. Оптимальный размер — до 1200 px по большей стороне.
2. **Ссылками.** Добавьте в Excel колонку «Фото» со ссылками `https://…` (несколько ссылок — через пробел или `;`).

У товара без фото показывается аккуратная заглушка с артикулом и надписью «Фото — по запросу». Чужие или «похожие» фото не подставляются.

## 2. Заявки и письма

Все формы отправляют данные на сервер, и письмо уходит на почту магазина. Форм четыре:

- оформление заказа;
- «Перезвоните мне»;
- «Подбор по VIN»;
- «Напишите нам» и «Спросить менеджера» о товаре.

Покупатель видит «Заявка отправлена» или номер заказа только после того, как сервер подтвердил отправку письма. Если отправить не удалось, покупатель видит понятную ошибку и телефон магазина.

**Как это устроено:**
- `server/handler.ts` — обработчик форм;
- `functions/api/[kind].ts` — он же в виде функции Cloudflare Pages;
- в `npm run dev` и `vite preview` тот же обработчик подключается из `vite.config.ts`.

**Защита:**
- **Проверка на сервере:** все поля проверяются заново, телефон приводится к формату +380…, длина полей ограничена, HTML в письме экранируется.
- **Цены в заказе:** сервер пересчитывает их по каталогу — цену из браузера он не принимает.
- **Количество:** не больше остатка.
- **Оплата:** для кузовных деталей и оптики сервер не примет наложенный платёж.
- **Защита от ботов:** скрытое поле-ловушка и минимальное время заполнения формы.
- **Лимит:** не больше 6 запросов в минуту с одного IP.
- **Только с сайта магазина:** запросы с чужих сайтов отклоняются (проверка Origin), поэтому форму нельзя использовать для рассылки спама.
- **Ключи** почтового сервиса хранятся только в переменных окружения хостинга, во фронтенде и в репозитории их нет.

**Настройки** (`.env.example`):

| Переменная | Что указать |
|---|---|
| `MAIL_PROVIDER` | `brevo` (по умолчанию) или `resend` |
| `MAIL_API_KEY` | API-ключ сервиса |
| `MAIL_FROM` | подтверждённый в сервисе отправитель, например `Asia Motor <info@asiamotor.com.ua>` |
| `MAIL_TO` | куда приходят заказы и заявки, например `info@asiamotor.com.ua` |
| `ALLOWED_ORIGINS` | только если сайт и API на разных адресах |

### Brevo — рекомендуемый вариант

Бесплатно до 300 писем в день, отправителя можно подтвердить одним письмом, без настройки домена.

1. Зарегистрируйтесь на brevo.com.
2. **Senders, Domains & Dedicated IPs → Senders → Add a sender:** укажите `info@asiamotor.com.ua` и подтвердите его по письму.
3. **SMTP & API → API Keys → Generate a new API key:** скопируйте ключ.
4. Впишите ключ и адреса в переменные хостинга (см. раздел 3).

Чтобы письма реже попадали в спам, добавьте в DNS домена записи SPF и DKIM, которые покажет Brevo (раздел Domains).

## 3. Хостинг: Cloudflare Pages

GitHub Pages умеет отдавать только статические файлы, поэтому на нём формы работать не могут. На https://k1s1l.github.io/AsiaMotor/ формы честно показывают ошибку и телефон.

Для работающего магазина нужен Cloudflare Pages: бесплатный хостинг, где сайт и обработчик форм живут на одном адресе.

1. Войдите на dash.cloudflare.com и откройте **Workers & Pages → Create → Pages → Connect to Git**. Выберите репозиторий `k1s1l/AsiaMotor`, ветку `main`.
2. Настройки сборки:
   - **Build command:** `npm run build && npx tsx scripts/prerender.ts`
   - **Build output directory:** `dist`
   - Папка `functions/` подключится автоматически.
3. **Settings → Variables and Secrets.** Добавьте:
   - `NODE_VERSION` = `22`;
   - `MAIL_API_KEY` — с типом **Secret**;
   - `MAIL_FROM`;
   - `MAIL_TO`.

   После этого нажмите **Retry deployment**.
4. **Custom domains → Set up a domain:** `asiamotor.com.ua`. Нужен доступ к DNS домена — у владельца или у регистратора.
5. В `src/lib/seo.ts` поменяйте `ORIGIN` на `https://asiamotor.com.ua`, чтобы canonical-ссылки, sitemap и микроразметка указывали на настоящий домен.

**Проверка после запуска:**
1. Оформите тестовый заказ и отправьте форму «Напишите нам».
2. Письма должны прийти на `MAIL_TO`.
3. Если письма нет, откройте **Workers & Pages → проект → Functions → Logs**: там видна причина, например неподтверждённый отправитель или неверный ключ.

### Если сайт остаётся на GitHub Pages

Задеплойте этот же репозиторий в Cloudflare Pages только ради API. Затем:
- при сборке для GitHub Pages укажите `VITE_API_URL=https://<проект>.pages.dev/api`;
- в Cloudflare задайте `ALLOWED_ORIGINS=https://k1s1l.github.io`.

## 4. Обновление каталога

1. Выгрузите прайс из 1С.
2. Выполните `npm run catalog:import -- прайс.xls`.
3. Проверьте отчёт: сколько товаров, что не разложено по разделам.
4. Сделайте коммит и пуш — хостинг пересоберёт сайт.

Если в будущем появится API или база данных 1С, формат `src/data/catalog.json` остаётся тем же. Тогда импорт можно запускать по расписанию (GitHub Actions) или заменить чтением из базы.
